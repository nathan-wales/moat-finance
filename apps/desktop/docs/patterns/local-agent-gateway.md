# Pattern: Local Agent Gateway (apps/desktop)

## Overview

The desktop app includes a local MCP HTTP gateway (`src/main/agent-gateway/`) that lets local AI agents (Claude Desktop, Cursor) connect to the user's local Moat Finance data without going through the cloud. It runs as a local HTTP server on `localhost:3030`.

```
Agent (Claude Desktop / Cursor)
  → POST|GET|DELETE http://localhost:3030/mcp (OAuth access token or Bearer moat_local_…)
    → local-token-service.ts / oauth-service.ts
      → scope-checker.ts (check scopes for requested tool)
        → MCP tool handler (read from SQLite via AppRuntime)
          → audit-log.ts (JSONL append to userDataPath/audit.jsonl)

  → POST http://localhost:3030/import/transactions[/preview] (Bearer + mcp:transactions:write)
    → previewTransactionImport / commitTransactionImport (packages/domain)
```

The gateway accepts MCP on `/mcp`, OAuth discovery and token endpoints, and JSON import on `/import/transactions/preview`, `/import/transactions`, and `/import/columns/detect`. Everything else is 404.

Streamable HTTP clients (including Cursor) use POST for JSON-RPC, GET for the standalone SSE stream, and DELETE to end a session. The gateway must accept all three on `/mcp`. Unauthenticated `/mcp` returns HTTP 401 with `WWW-Authenticate: Bearer resource_metadata="http://127.0.0.1:3030/.well-known/oauth-protected-resource"`. Clients that already hold a `moat_local_…` bearer token skip OAuth.

## Gateway lifecycle

```ts
// src/main/index.ts — initialization order matters
const desktop = await initDesktopDb(app.userData);
initGateway(app.userData, desktop.appCtx); // registers gateway deps
registerAllHandlers();  // registers IPC handlers (including agent IPC)
await createWindow();
```

`initGateway()` registers the `userDataPath` and `AppRuntime` but does **not** start the HTTP server. The gateway is started/stopped via IPC from the renderer:

```ts
// From the renderer (via IPC)
await window.moatDesktop.agent.startGateway();   // starts local HTTP server
await window.moatDesktop.agent.stopGateway();    // stops it
await window.moatDesktop.agent.getStatus();      // returns GatewayStatus
```

## local-token-service.ts

Manages agent tokens stored locally (not in the cloud DB). Tokens are stored on disk at `userDataPath/agent-tokens.json`:

- **Tokens are short-lived** — generated by the renderer UI ("Connect to your AI assistant" flow) and valid until manually revoked.
- **Tokens are hashed before storage** — the raw token is shown once to the user, the hash is stored.
- `resolveAgentToken(userDataPath, bearerToken)` validates an incoming token and returns an `AgentContext` (userId + scopes) or `null` if invalid.

## scope-checker.ts

The local scope-checker mirrors the cloud MCP app's scope model. Each tool requires a declared scope. The local gateway enforces this at request time.

**Never add a tool to the local gateway without declaring its required scope.** The `GatewayTool` type in `src/main/agent-gateway/types.ts` enforces this.

Local allowlists share one source of truth:

- Contracts: `packages/mcp-contracts/src/scopes.ts` → `desktopMcpScopes` (`mcpScopes` minus cloud-only `mcp:community-tips:*`)
- UI: `renderer/src/pages/mcp/scope-options.ts` → `desktopAgentAvailableScopes` / `defaultLocalAgentScopes`
- Enforcement: `agent-gateway/local-token-service.ts` → `localAgentScopes` / default `generateToken` scopes

One-click Claude, Cursor, and ChatGPT Desktop connect mint tokens with the full `desktopMcpScopes` set (reads plus financial writes, including `mcp:transactions:write`). Custom tokens keep the privacy picker and still default to that full set.

Cloud-only community-tips scopes stay off the desktop allowlist. `mcp:feedback:write` is allowed: `moat.submitFeedback` proxies to the public desktop feedback API. Register new local tools in `agent-gateway/tools/registry.ts`.

## audit-log.ts (JSONL)

Every tool invocation is logged to `userDataPath/audit.jsonl`. Each line is a JSON object:

```json
{
  "timestamp": "2025-05-26T12:00:00.000Z",
  "tool": "moat.listTransactions",
  "clientProfile": "claude-desktop",
  "userId": "local-user",
  "success": true
}
```

- The log is rotated automatically (see `rotateAuditLogIfNeeded`) to prevent unbounded growth.
- Audit entries must not include PII or sensitive financial values — only tool name, timestamp, and success/failure.

## vs. HTTP MCP gateway (`apps/mcp`)

| Dimension | Local gateway (`agent-gateway/`) | Cloud gateway (`apps/mcp`) |
|-----------|----------------------------------|---------------------------|
| Data source | Local SQLite (`@moat/db-sqlite`) | Cloud PostgreSQL (Neon) |
| Auth | Local token store + loopback OAuth (`agent-oauth.json`) | PAT or OAuth (DB-backed) |
| Transport | HTTP on `localhost:3030` | HTTP/SSE on Vercel |
| Rate limiting | None (local process) | Upstash Redis |
| Audit log | Local JSONL file | Axiom structured logs |
