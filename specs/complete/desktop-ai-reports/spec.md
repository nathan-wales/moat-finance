# Desktop AI Reports Page

## Status

Draft. Created June 8, 2026 after reviewing the web `/ai-reports` implementation, desktop navigation shell, `@moat/features` shared package patterns, `@moat/contracts` API client surface, `@moat/reports` renderer, cloud API/MCP report stack, and desktop IPC/MCP gateway gaps.

## Goal

Add a first-class **Reports** page to the desktop app under the `AI Assistant` navigation section, matching the web app's information architecture and visual design. Reports generated by a user's local MCP agent should appear in the desktop UI automatically.

Success means:

- Desktop sidebar has **Reports** as the first item in the `AI Assistant` section (matching web).
- Desktop users can list, open, and delete locally stored AI reports.
- Local MCP agents can create, update, list, share, and delete reports via the desktop gateway (same tool names as cloud MCP).
- UI presentation is shared through `packages/features` and consumed by both web and desktop.
- Web `/ai-reports` routes become thin wrappers over shared feature components.
- No regression to existing cloud report behavior on web.

## Product Context

Moat Finance's AI reports are structured financial artifacts (Moat Finance Canvas JSON documents) created by MCP agents on behalf of users. On web, agents write to Postgres via the cloud MCP gateway; users browse reports at `/ai-reports` and optionally share them via public links at `/r/[shareSlug]`.

Desktop is local-first: agents connect to `localhost:3030/mcp` and read/write local SQLite data. Reports created on desktop should live on the device alongside transactions and budgets — not require cloud connectivity to view.

The desktop Reports page should answer: *What financial reports has my local agent created, and what do they say?*

Web and desktop share the same visual language (report cards, detail viewer, Moat Finance Canvas renderer) but differ on sharing:

- **Web**: share links resolve to hosted `/r/[slug]` pages backed by Postgres.
- **Desktop v1**: reports are local-only; share-via-link is hidden until a cloud publish/sync story exists.

## Shared Component API Design

### Capabilities prop (platform feature flags)

```ts
type AiReportsCapabilities = {
  /** Whether share-via-link actions are shown. false on desktop v1. */
  shareViaLink: boolean;
  /** Whether V2 snapshot update is available. true on web, false on desktop v1. */
  updateSnapshot: boolean;
};
```

Default for web: `{ shareViaLink: true, updateSnapshot: true }`.
Default for desktop v1: `{ shareViaLink: false, updateSnapshot: false }`.

### Navigation callbacks

Shared components must not import `next/navigation` or call `window.open` directly.

```ts
type AiReportsNavigation = {
  openReport: (id: string) => void;
  closeReport: () => void;
};

// Web adapter:
//   openReport: (id) => window.open(`/ai-reports/${id}`, '_blank')
//   closeReport: () => router.push('/ai-reports')

// Desktop adapter:
//   openReport: (id) => nav.push(`/ai-reports?reportId=${id}`)
//   closeReport: () => nav.push('/ai-reports')
```

### Notifications

Follow the transactions `FeatureNotifications` pattern instead of importing `sonner` in `@moat/features`:

```ts
type AiReportsNotifications = {
  success: (message: string) => void;
  error: (message: string) => void;
};
```

Host apps wire to `sonner` (web) or a desktop toast.

### Share URL injection

```ts
type AiReportsPageProps = {
  capabilities?: AiReportsCapabilities;
  navigation: AiReportsNavigation;
  notifications?: AiReportsNotifications;
  shareBaseUrl?: string; // e.g. 'https://app.fin.ai' on web; omitted on desktop v1
  onConfirmDelete?: (message: string) => boolean; // replaces window.confirm
};
```

### ReportViewer decoupling

`report-viewer.tsx` currently owns share/unshare/updateSnapshot mutations via `useApiClient()`. Refactor to:

```ts
type ReportViewerProps = {
  report: AiReport;
  capabilities: AiReportsCapabilities;
  shareBaseUrl?: string;
  onClose: () => void;
  onShare?: () => Promise<void>;
  onUnshare?: () => Promise<void>;
  onUpdateSnapshot?: () => Promise<void>;
  onCopyLink?: (url: string) => void;
  notifications?: AiReportsNotifications;
};
```

Parent pages (`AiReportsPage`, `AiReportDetailPage`) own React Query mutations and pass handlers down. This matches how `TransactionsPage` injects `notifications`.

### AiReportDetailPage routing

Single shared component resolves report ID from prop OR navigation context:

```ts
type AiReportDetailPageProps = AiReportsPageProps & {
  reportId?: string; // web passes from Next.js params
};
```

When `reportId` is omitted, read `nav.getSearchParam('reportId')` (desktop pattern, same as prompts).

### Combined list + detail on desktop

Desktop can render a single page component that switches between list and detail based on `reportId` search param — or render two separate page entries in `App.tsx`. Recommendation: one `AiReportsPage` that internally shows list or detail (like `PromptLibraryPage` with detail panel), keeping desktop routing simple with only `/ai-reports` in the route map.

## Desktop Backend Plan

Reports on desktop require a full local data stack. This is the largest workstream.

### Phase A — SQLite schema

Add to `packages/db-sqlite/prisma/schema.prisma` (mirror cloud models, SQLite-adapted):

```prisma
model AiReport {
  id            String    @id @default(cuid())
  userId        String
  title         String
  description   String?
  sanitizedHtml String    @default("")
  sanitizedCss  String    @default("")
  visibility    String    @default("PRIVATE") // PRIVATE | SHARE_LINK | PUBLIC
  shareSlug     String?   @unique
  document      String?   // JSON stored as text in SQLite
  createdBy     String    @default("AGENT")
  createdAt     DateTime  @default(now())
  updatedAt     DateTime  @updatedAt
  deletedAt     DateTime?

  shares   AiReportShare[]
  versions AiReportVersion[]

  @@index([userId])
  @@index([userId, deletedAt])
}

model AiReportShare { ... }
model AiReportVersion { ... }
```

Add migration SQL in `packages/db-sqlite/prisma/migrations/`.

### Phase B — Repository layer

Add `AiReportRepository` interface to `packages/data-access`:

```ts
interface AiReportRepository {
  list(userId: string): Promise<AiReportSummary[]>;
  getById(userId: string, id: string): Promise<AiReport | null>;
  create(userId: string, input: CreateAiReportInput): Promise<AiReport>;
  update(userId: string, input: UpdateAiReportInput): Promise<AiReport>;
  softDelete(userId: string, id: string): Promise<void>;
  share(userId: string, id: string): Promise<CreateSnapshotResult>;
  unshare(userId: string, id: string): Promise<void>;
  updateSnapshot(userId: string, id: string): Promise<CreateSnapshotResult>;
}
```

Implement:

- `packages/data-access/src/sqlite/ai-report-repository.ts`

## Data And Security Requirements

- Report documents validated with `validateFinReportDocument` before persistence (local and cloud).
- V1 legacy HTML reports sanitized before storage (reuse existing sanitizer from API service when extracting to domain).
- Local MCP tools gated by `mcp:reports:write` scope via `assertScopes`.
- Renderer never imports Node.js, Prisma, or main-process modules.
- IPC payloads validated with Zod.
- Do not log report document content, share slugs with PII, or raw HTML in structured logs.
- Public share page (`/r/[slug]`) remains web/cloud only in v1 — desktop share slugs stored locally are not publicly resolvable until cloud publish exists.
- Soft-delete reports (`deletedAt`) matching cloud behavior.

## Open Questions

- **Should desktop v1 support share-via-link locally?** Recommendation: no. Hide share UI until cloud publish or a local HTTP share server is designed.
- **Should web open detail in same tab instead of new tab?** Recommendation: keep new-tab behavior on web for now; match existing UX.
- **Combined vs split page component on desktop?** Recommendation: single `AiReportsPage` with internal list/detail switch via `reportId` search param.
- **Migrate desktop budget to shared `BudgetPage` in same PR?** Recommendation: no — keep PRs single-purpose.
- **Postgres repository refactor in Phase 5?** Recommendation: defer to a follow-up PR after desktop ships.

## Non-Goals

- Cloud sync of reports between web and desktop
- Public share link hosting from desktop
- Report editing UI for users (agent-created only)
- Migrating `/r/[shareSlug]` public page to shared packages
- Changing Moat Finance Canvas block schema or renderer
- Adding report tools to desktop that bypass scope checks
